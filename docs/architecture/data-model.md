# Relational Data Model

PostgreSQL is the source of truth. The model is in **3NF by default**. Every exception is listed in the [denormalization register](#denormalization-register) with its reason and the mechanism that keeps it consistent. Without a register entry, a redundant column is a defect.

## Data categories

Each table belongs to exactly one category. The category decides who may write it and whether it may change.

| Category | Meaning | Mutability | Examples |
|----------|---------|------------|----------|
| **Reference** | Lookup data with attributes | Migrations only | `ref.currencies`, `ref.fee_types`, `ref.discrepancy_types` |
| **Source facts** | What a source said, normalized | Insert-only | `ingestion.payments`, `ingestion.bank_transactions` |
| **Operational** | Current state of aggregates | Updated through aggregate methods only | `investigation.cases`, `resolution.proposed_actions` |
| **Historical snapshot** | Frozen copy of something at a point in time, kept for audit | Insert-only, never updated | `ingestion.raw_records`, `investigation.evidence.snapshot`, `audit.events` |
| **Read model** | Query-optimized projection | Rebuildable. Never written by use cases | `read.case_queue`, `read.reconciliation_summary` |
| **Library-owned** | Tables a framework manages | Opaque to the domain | `agent_runtime.*` (LangGraph checkpoints) |

**Rule:** LangGraph checkpoints are never the source of truth for a business fact. Anything the agent concludes is persisted through Investigation use cases into `investigation.*`.

## Conventions

| Topic | Convention |
|-------|-----------|
| Primary keys | `UUID`, generated by the application through an `IdGenerator` (deterministic in tests) |
| Money | `amount_minor BIGINT NOT NULL` + `currency CHAR(3) NOT NULL REFERENCES ref.currencies(code)`. The minor-unit exponent lives in `ref.currencies`, not on each row |
| Signs | Amounts are stored positive with `CHECK (amount_minor > 0)`. Direction comes from the record type or an explicit `direction` column |
| Time | `TIMESTAMPTZ` for instants (stored UTC). `DATE` for business dates such as `value_date` |
| Lifecycle status | `TEXT` + `CHECK (status IN (...))`. Easier to migrate than native `ENUM` |
| Extensible reference sets | Lookup table in `ref`, used when values carry attributes (for example a default severity) |
| Natural keys | Always backed by a `UNIQUE` constraint, for example `(source_id, external_id)` |
| Cross-context FKs | Allowed only **upstream** in the context map, toward rows that are never deleted: `ref`, Ingestion canonical records, `recon.discrepancies`, `knowledge.document_chunks`. Never downstream, never sideways |
| Outbox | Every context that emits events has its own `<schema>.outbox` with the shape shown in `resolution` |

## Cross-source references are claims, not foreign keys

A gateway payment carries the order number the gateway *says* it belongs to. That is a fact about the source, not a verified link. It is stored as `order_external_ref TEXT`, **not** as an FK to `orders`. Verified links exist only in `recon.match_group_members`. This keeps the model honest when sources contradict each other (principle 10). It also gives the reconciliation engine something to check, instead of having the schema hide the mismatch.

## Schema by context

### `ref` (shared kernel)

```sql
ref.currencies(code CHAR(3) PK, minor_unit SMALLINT NOT NULL CHECK (minor_unit BETWEEN 0 AND 4))
ref.source_kinds(code TEXT PK)                 -- ecommerce, gateway, bank, authorization
ref.fee_types(code TEXT PK, description TEXT NOT NULL)
ref.discrepancy_types(code TEXT PK, description TEXT NOT NULL, default_severity TEXT NOT NULL)
```

### `ingestion`

```sql
data_sources(id PK, kind REFERENCES ref.source_kinds, name TEXT NOT NULL UNIQUE)
  -- seeded by migration: shop (ecommerce), gateway, bank, back_office (authorization)

import_batches(id PK, source_id FK NOT NULL, record_type TEXT CHECK IN (<the seven types>),
               file_name TEXT NOT NULL, file_sha256 CHAR(64) NOT NULL, status, row_count,
               started_at, finished_at,                -- set exactly when status is final
               UNIQUE (source_id, file_sha256),        -- re-importing a file is a no-op
               UNIQUE (id, source_id))                 -- target for composite FKs (register R1)
import_batch_errors(batch_id FK, ordinal INT, line_no INT NOT NULL,  -- 0 = the file itself
                    field TEXT NOT NULL, message TEXT NOT NULL, PRIMARY KEY (batch_id, ordinal))

raw_records(id PK, batch_id, source_id, line_no INT NOT NULL, payload JSONB NOT NULL,
            payload_sha256 CHAR(64) NOT NULL,      -- SHA-256 of the payload as canonical JSON
            FOREIGN KEY (batch_id, source_id) REFERENCES import_batches(id, source_id),
            UNIQUE (batch_id, line_no), UNIQUE (id, source_id))

-- Every canonical table also has: id PK, source_id, external_id, raw_record_id UNIQUE,
-- FOREIGN KEY (raw_record_id, source_id) REFERENCES raw_records(id, source_id),
-- UNIQUE (source_id, external_id); amounts are positive with a currency FK.
orders(... , customer_name, customer_email, amount_minor, currency, status, placed_at)
payments(... , order_external_ref TEXT, gateway TEXT NOT NULL, amount_minor, currency, captured_at,
         settlement_batch_ref)
refunds(... , payment_external_ref TEXT NOT NULL, gateway, amount_minor, currency, refunded_at,
        settlement_batch_ref)
fees(... , payment_external_ref TEXT NOT NULL, gateway, fee_type REFERENCES ref.fee_types,
     amount_minor, currency, settlement_batch_ref)
settlements(... , gateway TEXT NOT NULL, batch_date DATE NOT NULL,   -- gateway report: declared net (ADR-0011)
            net_amount_minor, currency)
bank_transactions(... , account_ref, direction CHECK IN ('credit','debit'), value_date DATE,
                  amount_minor, currency, description TEXT,
                  description_tsv TSVECTOR GENERATED ALWAYS AS (to_tsvector('simple', description)) STORED)
authorizations(... , subject_kind CHECK IN ('refund','write_off'), subject_external_ref TEXT,
               approved_by TEXT NOT NULL, approved_at, max_amount_minor, currency)

source_conflicts(id PK, source_id, record_type TEXT, external_id, existing_raw_record_id,
                 incoming_raw_record_id UNIQUE, detected_at,
                 FOREIGN KEY (existing_raw_record_id, source_id) REFERENCES raw_records(id, source_id),
                 FOREIGN KEY (incoming_raw_record_id, source_id) REFERENCES raw_records(id, source_id))
outbox(id BIGINT IDENTITY PK, event_type, event_version, payload JSONB, created_at, published_at NULL)
```

`raw_records` is an immutable snapshot of what arrived. The canonical rows are typed and queryable. A re-sent record with a different `payload_sha256` creates a `source_conflicts` row, never an update; the first record seen keeps the canonical row. A re-send with the same payload only adds its raw record. Imports of one source are serialized by a transaction-scoped advisory lock.

### `recon`

```sql
fee_schedules(id PK, gateway TEXT, fee_type REFERENCES ref.fee_types, rate_bps INT CHECK (>= 0),
              fixed_minor BIGINT CHECK (>= 0), currency, valid_during DATERANGE NOT NULL,
              policy_document_id UUID NULL,   -- attribution only; no FK (Knowledge is not upstream of Recon)
              EXCLUDE USING gist (gateway WITH =, fee_type WITH =, valid_during WITH &&))

reconciliation_runs(id PK, period DATERANGE NOT NULL, ruleset_version TEXT NOT NULL, status,
                    started_at, finished_at, UNIQUE (period, ruleset_version), UNIQUE (id))

match_groups(id PK, run_id FK, rule_code TEXT NOT NULL, created_at, UNIQUE (id, run_id))

match_group_members(id PK, group_id, run_id,
                    order_id FK NULL, payment_id FK NULL, refund_id FK NULL,
                    fee_id FK NULL, bank_transaction_id FK NULL,
                    role TEXT NOT NULL,
                    FOREIGN KEY (group_id, run_id) REFERENCES match_groups(id, run_id),
                    CHECK (num_nonnulls(order_id, payment_id, refund_id, fee_id, bank_transaction_id) = 1),
                    UNIQUE (run_id, payment_id), UNIQUE (run_id, bank_transaction_id), ...)

discrepancies(id PK, run_id FK, type REFERENCES ref.discrepancy_types, severity,
              expected_minor BIGINT, actual_minor BIGINT, currency,
              delta_minor BIGINT GENERATED ALWAYS AS (actual_minor - expected_minor) STORED,
              fingerprint CHAR(64) NOT NULL UNIQUE, status CHECK IN ('detected','superseded'))

discrepancy_records(discrepancy_id FK, <same one-of-five FK columns as members>, CHECK (num_nonnulls(...) = 1))
```

Notes:

- The engine computes match candidates in memory. Only confirmed groups are persisted, which is what makes `UNIQUE (run_id, payment_id)` a correct "at most one group per run" rule.
- Member amounts are **not** stored. They come from a join to the source record.
- The fee rates rules need are relational (`fee_schedules`), not text parsed by an LLM. The policy document is linked for attribution only.
- A discrepancy has no investigation lifecycle. That status lives on `investigation.cases`. Storing it twice would create a transitive dependency.

### `investigation`

```sql
cases(id PK, discrepancy_id UUID NOT NULL UNIQUE REFERENCES recon.discrepancies, status, priority,
      assignee_id, opened_at, closed_at, version INT NOT NULL)

agent_runs(id PK, case_id FK, thread_id TEXT NOT NULL UNIQUE, graph_version TEXT NOT NULL,
           model TEXT NOT NULL, prompt_version TEXT NOT NULL, trace_id TEXT, status,
           input_tokens INT, output_tokens INT, started_at, finished_at)

calculations(id PK, case_id FK, formula_code TEXT NOT NULL, result_minor BIGINT NOT NULL, currency,
             computed_at)
calculation_inputs(calculation_id FK, ordinal INT, <one-of-five source record FK columns>,
                   PRIMARY KEY (calculation_id, ordinal))

evidence(id PK, case_id FK, agent_run_id FK,
         order_id NULL, payment_id NULL, refund_id NULL, fee_id NULL, bank_transaction_id NULL,
         authorization_id NULL, document_chunk_id NULL, calculation_id NULL,
         CHECK (num_nonnulls(...) = 1),
         snapshot JSONB NOT NULL, snapshot_sha256 CHAR(64) NOT NULL, captured_at)

findings(id PK, case_id FK, agent_run_id FK, hypothesis TEXT NOT NULL, conclusion TEXT NOT NULL,
         confidence NUMERIC(3,2) CHECK (confidence BETWEEN 0 AND 1), recorded_at)
finding_evidence(finding_id FK, evidence_id FK, PRIMARY KEY (finding_id, evidence_id))
```

Evidence uses one FK column per target type with `num_nonnulls(...) = 1`, never a `(kind, ref_id)` pair. The database keeps real referential integrity that way.

### `knowledge`

```sql
documents(id PK, kind CHECK IN ('policy','contract','sop','correspondence'), title, version INT,
          content_sha256 CHAR(64) UNIQUE, embedding_model TEXT NOT NULL, effective_from DATE)
document_chunks(id PK, document_id FK, ordinal INT, content TEXT NOT NULL,
                content_tsv TSVECTOR GENERATED ALWAYS AS (...) STORED,
                embedding VECTOR(N) NOT NULL,          -- N fixed by ADR-0006
                UNIQUE (document_id, ordinal))
-- Indexes: GIN (content_tsv), HNSW (embedding)
```

`embedding_model` sits on the document, not on each chunk. Every chunk of a document version is embedded with the same model (an aggregate invariant).

### `resolution`

Class-table inheritance replaces a free-form `payload JSONB`. Each action type has typed columns.

```sql
proposed_actions(id PK, case_id UUID NOT NULL, proposed_by_run_id UUID NOT NULL,
                 action_type CHECK IN ('adjustment','refund_request','write_off'),
                 status, idempotency_key TEXT NOT NULL UNIQUE, version INT NOT NULL, proposed_at,
                 UNIQUE (id, action_type))
action_adjustments(action_id PK, action_type CHECK (= 'adjustment'), amount_minor, currency,
                   direction, target_payment_id NULL, target_bank_transaction_id NULL,
                   FOREIGN KEY (action_id, action_type) REFERENCES proposed_actions(id, action_type))
action_refund_requests(...)   -- same pattern
action_write_offs(...)        -- same pattern

approvals(id PK, action_id FK, decision CHECK IN ('approved','rejected'), decided_by TEXT NOT NULL,
          reason TEXT NOT NULL, decided_at, UNIQUE (action_id, decided_by))

adjustment_entries(id PK, action_id FK UNIQUE, amount_minor, currency, executed_at)
outbox(id PK, event_type, event_version, payload JSONB, created_at, published_at NULL)
```

The composite FK `(action_id, action_type)` guarantees that a detail row matches its parent's type. The final action type set is defined by ADR-0008.

### `audit`

```sql
events(id BIGINT GENERATED ALWAYS AS IDENTITY PK, occurred_at, actor_type CHECK IN ('user','agent','system'),
       actor_id TEXT NOT NULL, aggregate_type TEXT, aggregate_id UUID, event_type TEXT,
       event_version INT, payload JSONB NOT NULL, prev_sha256 CHAR(64), sha256 CHAR(64) NOT NULL UNIQUE)
-- The application role gets INSERT and SELECT only. UPDATE and DELETE are revoked.
```

### `read` (read models)

Views or materialized views only, for example `case_queue` (case + discrepancy + amounts + age) and `reconciliation_summary` (per run). Dropping and rebuilding the `read` schema loses no data.

## Denormalization register

| ID | Where | What is redundant | Justification | Consistency strategy |
|----|-------|-------------------|---------------|----------------------|
| R1 | `raw_records.source_id`, canonical `*.source_id` | Derivable via `raw_record → batch → source` | Required by the natural key `UNIQUE (source_id, external_id)` | Composite FKs `(raw_record_id, source_id)` and `(batch_id, source_id)` make drift impossible in the database |
| R2 | `discrepancies.delta_minor` | `actual − expected` | Sorting and filtering by impact | `GENERATED ALWAYS ... STORED`. The database computes it |
| R3 | `discrepancies.fingerprint` | Hash of type + records + period | Idempotent re-runs never duplicate discrepancies | Computed by the domain once, immutable, `UNIQUE` |
| R4 | `match_group_members.run_id` | Derivable via `group → run` | Enforces "at most one group per record per run" with `UNIQUE` | Composite FK `(group_id, run_id)` |
| R5 | `evidence.snapshot` (JSONB) | Copy of the referenced row or chunk | Audit: the record must show exactly what the agent saw, even if sources are later corrected | Insert-only, `snapshot_sha256` verified by tests |
| R6 | `raw_records.payload` (JSONB) | Same data as the canonical row | Lineage: the original bytes as received | Insert-only. The canonical row is parsed from it exactly once |
| R7 | `proposed_actions.status` | Partly derivable from approvals + execution | The aggregate's current state, with an optimistic lock | Changed only by aggregate methods in the same transaction as the approval/execution insert. Invariant tests |
| R8 | `adjustment_entries.amount_minor` | Same as the approved action amount | Frozen record of what was executed | Insert-only. Domain asserts equality at execution |
| R9 | `audit.events.payload`, `outbox.payload` (JSONB) | Copies of aggregate state at event time | Event history and transport | Insert-only. Shape versioned by `event_version` |
| R10 | `*_tsv` columns | Derivable from text columns | Full-text search performance | `GENERATED ALWAYS ... STORED` |

## Constraints worth testing

Integration tests run against a real PostgreSQL and assert that the database itself rejects:

- Two imports of the same file for one source.
- A record in two match groups of the same run.
- An evidence row pointing to zero or two targets.
- Overlapping fee schedule periods.
- An action detail row whose type differs from its parent's type.
- `UPDATE` or `DELETE` on `audit.events` by the application role.
